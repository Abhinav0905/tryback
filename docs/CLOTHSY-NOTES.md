# Clothsy API: what TryBack relies on, and the evidence

Reconciled on 2026-11-06 against the public docs at <https://clothsyai.fabricvton.com/docs/api> (every linked page) and the source of the official SDK, `clothsy-ai@0.1.1` (npm, published 2026-10-03, tarball sha1 `6657ce6d…9765`). SDK references are `dist/<file>.js:<line>` inside that tarball. The client is `lib/tryon/clothsy.ts`; it implements the REST API directly and does not depend on the SDK.

**Status:** *verified* means the docs or the SDK source state it. *Unverified* means neither does, so `npm run probe` measures it and writes the result to `probe/REPORT.md`.

## What the first live run settles

Put 3 consenting adults' photos in `probe/people/` and run the command `npm run doctor` prints, adding `--i-have-consent` once everyone has agreed: `npm run probe -- --people probe/people --skus <a,b> --max-credits 7 --check-replay --i-have-consent`. Its `--skus` are SKUs whose product images are photos, preferring the ones the hero demo renders; without `--skus` the probe makes the same pick, and it refuses drawn product images unless `--allow-drawings`. Three people × two SKUs gives 6 renders, the minimum `npm run tune -- --apply` needs (two people give only 4). Then read the **Recommendations** section of `probe/REPORT.md`:

- **Rows 10–11.** It shows the headers on `POST /tryons`, the replay's HTTP status, and whether a re-sent key cost 0 credits (verdict FREE, CHARGED or INCONCLUSIVE). If it reports CHARGED, the README's "a reused Idempotency-Key never charges twice" and the free-replay accounting must change.
- **Rows 17–19.** It shows the output size and aspect against the photo, any added padding, the content type, and whether the AI label is present. If it says the centre-crop assumption is wrong, the gate (`lib/cv/gate.ts`) has to strip the border first.
- **Row 21.** It confirms or corrects the `/account` shape. Credits used are reconciled against the renders the client counted as charged.

`probe/observed.json` holds the same data, machine-readable.

## Claude diagnosis (for completeness)

`lib/diagnosis.ts` was checked against the claude-api skill (TypeScript) and `@anthropic-ai/sdk@1.6.0`:

- **Request.** `client.messages.parse({ model: DIAGNOSIS_MODEL (default claude-opus-5-5), max_tokens: 4000, output_config: { effort: "low", format: zodOutputFormat(schema) }, system, messages })`. `thinking` is not set, because Opus 5.5 always thinks adaptively and effort is the control.
- **Never hangs.** Each request has `{ timeout: 8000, maxRetries: 1, signal }`, and an 8 s deadline aborts the call and falls back to `diagnoseWithRules`.
- **Fallback to rules.** The rules also run on refusal (`stop_reason === "refusal"`, category logged), on unparseable output (`parse()` throws `AnthropicError`, which also covers a refusal or truncated reply that isn't JSON), and on every SDK error class.
- **Text only.** The request carries product attributes, tapped chips, the note with emails and phone numbers redacted, and two garment numbers. It never includes the photo, the customer or the order.
- **Zero-token key check.** `npm run doctor` validates the key with `client.models.retrieve(DIAGNOSIS_MODEL)` (`GET /v1/models/{id}`).
- **Server-side `fallbacks` not enabled.** It would need a beta header, and a model fallback can't fit inside the 8 s budget, so the deterministic rules are the fallback.
