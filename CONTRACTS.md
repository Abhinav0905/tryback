# TryBack — build contracts

TryBack is an exchange-first returns portal for a fictional DTC fashion brand ("Fernweave"). When a shopper returns an item because the style or colour didn't work, they take one photo **wearing the item they're sending back**. While they fill in the reason form, TryBack renders in-stock alternatives on that photo with the sponsor's virtual try-on API (Clothsy AI by FabricVTON). Each render passes a source-aware fidelity gate before it's shown, and the refund becomes a one-tap exchange. Size returns use the returned garment as a ruler: its known length gives px/cm, and the app draws measured hem lines for other sizes or length variants at **zero credits**. A merchant dashboard shows refunds avoided, revenue retained, credits per return, per-SKU diagnoses, and the try-on API's latency and gate pass rate by transition type.

This file is the **source of truth** for module boundaries. Each module has one owner. Implement to these signatures exactly; if you must add an export, add it, but don't rename or remove anything listed here.

Clothsy REST details (verified from docs, 2026-11-06):

- Base URL: `https://api.clothsyai.fabricvton.com/api/v1`.
- Auth: `Authorization: Bearer <key>`, server-side only.
- `POST /images`: multipart field `file` (JPEG or PNG, ≤4 MB) → `201 { id: "img_…", expiresAt }`. The id is valid for 24 h. Uploads cost no credits and are limited to 30/min. Cache ids by sha256 in `db.imageIds` and reuse them until `expiresAt − 1h`.
- `POST /tryons`:
  - Headers: `Idempotency-Key` (required, 8–128 chars) and `Content-Type: application/json`.
  - Body: `{ personImageId, garmentImageId, title, consent: true }`. Exactly one person field and one garment field.
  - Response: `202 { id, status: "pending", pollUrl }`.
  - Limited to 12 starts/min per account. Use a process-wide sliding-window limiter: **at most 10 starts in any 60 s**.
- `GET /tryons/{id}` → `{ id, status: "pending"|"success"|"failed", resultUrl|null, message? }`.
  - Poll every 2500 ms and give up after 150 s (`TIMEOUT`). Poll retries and their waits are bounded by that budget (+10 s for the last poll).
  - On success, download `resultUrl` **immediately**: it requires no auth and expires after 24 h.
  - `status: "failed"` means the credit was refunded. Map it to `TryOnError('RENDER_FAILED', message, false)`.
- Errors are JSON `{ error, code }`:
  - **Retry with the same Idempotency-Key** on 429 `RATE_LIMITED` (honour `Retry-After` seconds), 500 `INTERNAL_ERROR`, 502 `START_FAILED`, 503 `UNAVAILABLE`, and network errors. Back off 1 s, 2 s, then 4 s, for at most 4 attempts.
  - **Don't retry**: 400 (`MISSING_IDEMPOTENCY_KEY`, `INVALID_IMAGE_URL`, `IMAGE_DOWNLOAD_FAILED`, `UNSUPPORTED_IMAGE`, `INVALID_IMAGE_ID`), 401 `INVALID_API_KEY`, 402 `INSUFFICIENT_CREDITS`, 403 `CONSENT_REQUIRED`, 413 `IMAGE_TOO_LARGE`, 422 (`PERSON_PHOTO_REJECTED`, `IMAGE_REJECTED`, `GARMENT_REJECTED`).
  - On `INVALID_IMAGE_ID`, drop the cached image id, re-upload, and try **once** more with key `<key>_u1` (never `_r<n>`, the orchestrator's attempt namespace).
- Credits: 1 credit per *finished* try-on. Failed and unstarted try-ons are refunded. A reused idempotency key never charges twice. New accounts get 20 free credits.
- Every result carries an AI-content label. The UI shows "AI-generated preview".

- `GET /account` → `{ credits, scope }` (`fetchClothsyAccount()` never throws; `npm run doctor` uses it, 0 credits).
- A replay is detected from `status: "success"` on the first start attempt (a new try-on always starts `pending`); renders carry a `replayed` flag. Replay headers are only a secondary signal. Evidence for every behaviour: `docs/CLOTHSY-NOTES.md`.
- Process-wide limiters: at most 10 starts, 25 uploads and 50 status polls in any 60 s.

`scripts/probe.ts` (`npm run probe -- --i-have-consent --people probe/people [--skus <a,b>] --max-credits 4 [--check-replay] [--allow-drawings] [--dry-run]`) is the day-1 probe matrix:

- Refuses to upload without `--i-have-consent`. Reads the account's credits first and refuses if the worst case exceeds them or `--max-credits` (default 4).
- Without `--skus` it picks two SKUs whose product images are photos (`suggestProbeSkus`, the doctor's pick). A live run refuses SKUs whose product image is a generated drawing unless `--allow-drawings`.
- Uploads each person photo × SKU, prints a plan, and enforces `--max-credits`.
- Writes `probe/out/<person>__<sku>.jpg`, appends JSON lines to `probe/results.jsonl` (`latencyMs`, `status`, `code`), and writes `probe/REPORT.md` + `probe/observed.json` (output size/padding, replay verdict, account shape).
- Uses `ClothsyProvider` directly and respects the rate limit. `npm run doctor` prints a probe command whose SKUs have photographed product images, without `--i-have-consent` (the operator adds it).

`lib/live.ts`: `export async function allowLiveFromRequest(req: Request): Promise<boolean>`. It returns `!config.liveAccessCode ? publicLiveAllowed() : cookie tb_live === config.liveAccessCode`, where `publicLiveAllowed()` is `NODE_ENV !== "production" || ALLOW_PUBLIC_LIVE=1`. Also: `adminAuth`/`adminGate` (ADMIN_TOKEN, constant-time; the right token is checked before the failure rate limit, so wrong guesses can't lock the admin out) and `viewerHashFromRequest`.

Hardening (`lib/ratelimit.ts`, `lib/bodyLimit.ts`): per-client + global fixed 10-minute windows (429 `RATE_LIMITED` with `Retry-After`; the client key comes only from the header the host's proxy sets, see `CLIENT_IP_HEADER`), streamed body caps (photo request 4.5 MB → 413 `PHOTO_TOO_LARGE`; JSON 64 KB). Retention (`lib/retention.ts`, started by `instrumentation.ts` → `lib/boot.ts`): an hourly sweep deletes photos within 24 h of upload (clearing `r.photo`, keeping `r.consent`) and cached renders within 14 days (each sweep deletes what would pass its limit before the next sweep: `sweepLeadMs`); pinned renders are exempt.

Gate metrics:

| Metric | How to compute it |
|---|---|
| `colourDeltaE` | Expected colour = `hexToLab(target.colorHex)` + lighting offset (`observedGarmentLab − hexToLab(source.colorHex)`, clamped to ±25 per channel). Compare it with `meanLabMasked` over the render's clothes mask. |
| `residueFraction` | Fraction of render clothes-mask pixels whose Lab is within ΔE<10 of `observedGarmentLab`. Compute it only when ΔE(source, target) > 20, otherwise null. |
| `silhouetteIoU` | IoU of the worn garment vs the rendered garment (each image's clothes mask refined by its garment colour, so trousers/layers don't count), after the render is resized to the original's frame (centre-cropped, not stretched, if its aspect differs by >2%). |
| `identityDiff` | Mean absolute grayscale difference (0..1) inside the face mask bbox. |
| `hemErrorCm` | Requires calibration. Expected hem y is `observedHemY + (target.poms[targetSize].hpsToHemCm − purchasedPom.hpsToHemCm) × pxPerCm` (the size overlay's anchor; equals `hpsY + target length × pxPerCm` under garment calibration); error is `\|findHemY(renderMask) − expected\| / pxPerCm`. |
| `garmentCoverage` | Render clothes mask over the torso box. |

The pure parts are testable. Subsample pixels so a gate run takes under 1.5 s.

### D. Shopper UI: `app/page.tsx`, `app/r/**`, `components/shopper/**` (owner: **shopper-ui**)

Pages and polling:

- `/` is the landing page. Hero: "Try-on before purchase sells. TryBack keeps the sale." Links to `/r`, `/merchant`, `/demo`, `/bench`, plus a mode pill from `/api/status`.
- `/r` is order lookup: order number + email, plus quick-fill buttons for demo orders 1042, 1043 and 1044 with email `demo`.
- `/r/order/[orderId]?email=` lets the shopper pick a line, then `POST /api/returns` and route to `/r/[returnId]`.
- `/r/[returnId]` is a client `ReturnFlow` that polls `GET /api/returns/[id]`: every 1.5 s while any job is queued or running, otherwise every 6 s, and stops when resolved.

Mobile-first, max width ≈ 460px, centred. Every screen until resolution has a visible "Skip to refund" in the footer.

The flow by step:

1. **Reason.** Three large options:
   - "Style or colour didn't work".
   - "Fit or size". Multi-select `FIT_CHIPS`, then continue.
   - "Something else (damaged, late, changed mind)". Goes straight to refund confirmation.
2. **Photo offer.** Copy: "See 3 swaps on you — about 20 seconds · +$10 exchange bonus". For fit: "We'll measure the other sizes on the photo — no AI needed". Then:
   - Consent checkbox: "I'm 18 or older, I'm the person in the photo, and TryBack may send it to its try-on provider (Clothsy AI) to create previews. TryBack deletes its copy within 24 hours of upload and the previews within 14 days; Clothsy deletes uploads within 35 days." (Enforced by the hourly retention sweep; the 35 days are Clothsy's documented deletion.)
   - Tips: "Wear the item; full body; arms relaxed; keep tags on".
   - Buttons "Take photo" / "Upload photo" / "Skip photo".
3. **Capture.**
   - Camera: `getUserMedia({ video: { facingMode: 'user' } })` with a pose-silhouette SVG guide and live coaching from `liveCoach` (~4 fps), plus a 3-second timer. Un-mirror on capture.
   - Upload fallback: file input with `accept="image/*"` and `capture="user"`.
   - After capture, show `runPreflight` checks in a `PreflightChecklist` with fix prompts. Retake on failure.
   - Show "Continue anyway (dev)" only when `/api/status` reports `activeProvider === 'dev'`.
   - On success: `buildMeasurements` with purchased size/POM/colour, then POST photo.
4. **Style/colour form**, while speculative renders run:
   - Multi-select `STYLE_CHIPS` plus an optional text box.
   - Show dimmed skeleton cards and the `HonestClock` (renders started at photo upload; live ticking timer).
   - Submit with POST form.
5. **Results.**
   - The real photo is pinned as "What you have now".
   - Show the diagnosis summary.
   - `RenderCard`s for each candidate in rank order:
     - **Content:** the render (or skeleton), name + `Swatch`, the `why` text, price diff, stock.
     - **Labels:** gate badge (✓ Checked / badge text / "Re-checking…" while a retry runs), "AI-generated preview" or "Simulated preview".
     - **Compare slider:** real photo vs render.
     - **Action:** a "Swap for this" button.
   - Hide drop-verdict cards behind "1 preview didn't pass our quality check".
   - **Client gate runner:** when a job is `success && gate === null && !supersededBy` and on screen (a size preview, or after the form a SKU in `candidates`), run `runGate` (one at a time, client-side, in candidate rank order) and POST the result. `canRetry` is false for size previews and non-candidates. A gate the server rejects for good is replaced once by the "not auto-checked" fallback.
   - **HonestClock line:** "Renders started at photo upload · form done 0:24 · first card 0:27 (3 s after form)". A photo added after the form is timed from the photo only; with no first card and nothing rendering it reads "no previews could be shown" and stops.
6. **Size path** (`fit_size`):
   - `SizeLinesOverlay` (SVG over the real photo): solid line at the observed hem ("what you're wearing"), dashed lines with ± bands for each `SizeOption` (`projectSizeLines`), plus labels.
   - A list of options with deltas and tradeoffs, and the recommended one highlighted.
   - Show a grading callout when relevant.
   - "Swap to …" button, and an optional "Preview on me (1 credit)" that POSTs size-preview.
   - Copy: "Try-on can't show size, so we don't fake it — these lines are measured from the garment you're wearing."
   - If calibration is null, fall back to a table-only view.
7. **Exchange confirm.** Swap X (size) → Y (size), price difference, "ships today (instant exchange)". POST resolve, then the Done screen ("Exchange confirmed — your new item ships today"; "Refund avoided" is merchant wording and stays on the dashboard toast). The refund path has its own Done screen.
8. **No-photo path.** Alternatives shown on catalogue imagery: 0 credits, `rankCandidates` after the form.

### F. Assets & docs: `scripts/gen-placeholders.ts`, `public/catalog/*`, `README.md`, `docs/**`, `LICENSE` (owner: **assets**)

`npm run assets` generates `public/catalog/<sku.id>.png` (and `<sku.id>-alt.png` when `altImage` is set) for every SKU:

- 768×1024 placeholder product shots. White background, the garment centred, drawn as an SVG flat (silhouette by category/silhouette/lengthClass/neckline/sleeve, filled with `colorHex`, subtle shading and seams), rasterised with sharp.
- The alt image is a visibly different presentation: ghost-mannequin angle or hanger.
- No text inside the images.
- Each file carries a PNG tEXt marker (`TryBack=placeholder`; every committed drawing has it). Classification (`classifyCatalogFile`) is by marker only: an unmarked file of any size is a hand-placed photo. The generator never overwrites imported (`TryBack=catalog-import`) or hand-placed photos, even with `--force`.

`npm run catalog:import` (`scripts/import-catalog.ts`) renders photographed families from `assets-src/catalog/manifest.json` (source photo + licence per family; `photo`, `drawing` or `manual`): background matte, one px-per-cm scale per category (capped at the drawings' scale, `placeholderPxPerCm`, so photos and drawings compare in length), Tall/Petite stretch, CIELAB recolour to each `colorHex`, same 768×1024 frame. It also writes `public/catalog/CREDITS.md` and `credits.html` (linked from the shopper footer).
